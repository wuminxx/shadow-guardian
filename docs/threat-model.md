# 威胁模型

做 OPSEC 前先定清楚**防谁**。不同对手对应完全不同的成本，做多了浪费，做少了裸奔。

---

## 四个必答问题

### 1. 防谁？

| 对手 | 能力 | 需要的档位 |
|---|---|---|
| **同机其他用户 / 共享电脑** | 读你的文件 | A（文件权限 + 清理） |
| **本地取证（执法/司法鉴定）** | 完整磁盘镜像、恢复已删文件 | B~C（加密是唯一解） |
| **网络中间人（ISP/公司网络/公共 WiFi）** | 看流量元数据，TLS 内看不到 | B（隧道 + 无日志代理） |
| **AI 服务商** | 看你的全部输入输出，可留存、可人工审核 | B（零留存渠道）或 C（自托管） |
| **未来法律调取** | 从服务商处取历史数据 | B~C（换账号 + 自托管） |
| **数据泄漏连带** | 服务商被黑，你的数据出现在泄漏里 | B~C（不把敏感数据交给第三方） |
| **国家级** | 全链路 + 供应链 + 硬件 | C（硬件隔离 + air-gap） |

### 2. 保什么？

```
真实身份        → 提示词脱敏 + 账号隔离 + 语言/时区对齐
商业秘密        → 自托管或零留存 + 代码脱敏
第三方个人信息  → 法律义务，不能仅靠脱敏（见下）
不想被训练      → 关训练开关 / 零留存渠道 / 自托管
任务内容本身    → 全面档位 C
```

### 3. 时间窗？

```
一次性任务   → 可接受高成本：一次性 VM、新账号、任务后销毁
长期使用     → 需要可持续的基线：tmpfs、无日志代理、分离身份
```

### 4. 对手能力？

```
脚本小子     → 档位 A 足够
商业取证     → 档位 B，必须加密
国家级       → 档位 C，必须硬件隔离
```

---

## 默认假设（没有更好信息时）

```
· 会话记录永久留存，且可能被调取
· 网络链路全程可观测（元数据层）
· AI 厂商默认留存，除非明确关闭
· 你的措辞习惯、时区、语言组合本身可指纹
· 你删除的文件在 SSD 上可能仍可恢复
```

按最坏假设设计，按实际需要降低。

---

## 归因面（对手能看到什么）

真实的归因不靠单一证据，靠**多源交叉**。你的目标是让每个源都断掉。

```
源 1  基础设施     IP、ASN、托管商、端口、证书
源 2  时间         时区、活跃时段、作息规律
源 3  语言         用词、拼写、措辞习惯、code-switch
源 4  内容         提示词里的身份字段、项目代号、专有名词
源 5  账号         邮箱、支付、昵称、头像、跨服务复用
源 6  客户端       落盘文件、telemetry ID、版本指纹
源 7  行为         并发模式、节奏、工具偏好、错误模式
源 8  关联         跨会话、跨账号、跨项目的同一性
```

**任何单一源断了都不够** —— 攻击者用剩下的源做关联。要断的是"这些源能否指向同一个人"。

## 真实案例的破点（2026）

| 案例 | 破点 | 属于哪个源 |
|---|---|---|
| 韩国银行 AI 攻击 | 开放目录暴露工作台 | 源 1 |
| 韩国银行 AI 攻击 | 提示词写真实姓名/手机/学校/住址 | 源 4 |
| 韩国银行 AI 攻击 | Telegram 账号跨三案复用 | 源 5 + 源 8 |
| PaperCut 案 | 固定文件名 `pc-system.hiv` | 源 6 |
| PaperCut 案 | 固定账号 `Administrator17` | 源 6 |
| PaperCut 案 | 固定 IP 长期复用 | 源 1 |
| 台湾政府 AI 攻击 | 160MB 工作目录裸奔公网 | 源 1 |
| 台湾政府 AI 攻击 | 内部简体 + 对外繁体（code-switch） | 源 3 |
| Hugging Face | agent 上网找答案，行为异常 | 源 7 |
| GTG-10007 | 真实身份与学校/实习/求职轨迹同源 | 源 5 + 源 8 |

**结论**：技术层伪装做得再好（多国 IP、多代理、多模型），**只要有一个源暴露真实身份或基础设施，全部归零**。

## 不做的事

```
× 不用"绝对无法被发现"这种承诺 —— 技术上不存在
× 不承诺"换个说法就行" —— 语义等价会被聚类
× 不忽略法律义务 —— 技术脱敏不免除《个保法》责任
```

OPSEC 的目标不是"零风险"，是**把风险降到与收益匹配的水平**，并且知道自己在做哪个权衡。

---

## 第三方个人信息的特殊处理

涉及**他人**的个人信息时，技术手段不够 —— 触发法律义务：

```
《个人信息保护法》
  第 23 条   向第三方提供须取得单独同意，告知接收方名称、联系方式、
             处理目的、个人信息种类
  第 38~39 条 出境须具备安全评估 / 认证 / 标准合同之一，并另行单独同意
  第 55 条   事前开展个人信息保护影响评估
  第 57 条   发生泄露须通知履行义务的个人并报告

《国家网络安全事件报告管理办法》（2025-11-01 施行）
  触发上报义务
```

**脱敏降低风险，但不改变行为性质**：把第三方个人信息送进境外模型，在《个保法》下仍是"对外提供 + 出境"。

正确做法：能自托管就自托管；必须用第三方服务时，走合规路径而不是只做技术脱敏。
