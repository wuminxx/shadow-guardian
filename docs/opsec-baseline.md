# AI OPSEC 基线

这一篇合并了原来 `docs/` 下的七篇。只保留**别的文档不会告诉你的部分**——通用 OPSEC 常识不在此重复。

---

## 1. 核心事实：AI 客户端把完整对话写盘

这是本项目唯一真正的增量知识点。

AI CLI / IDE 扩展把**每一轮对话、每次工具调用、每个工具结果**以明文写进固定路径。不是加密、不是二进制、不是临时文件。

### 已知落盘面

```
~/.claude/projects/<cwd-slug>/*.jsonl    完整 transcript（明文 JSONL）
~/.claude/history.jsonl                  输入过的每条 prompt
~/.claude/memory/                        跨会话 memory
~/.claude/shell-snapshots/               shell 快照（含 env 变量！）
~/.claude/todos/                         任务清单
<project>/.claude/settings.json           项目级配置 —— 会被 git 提交
```

其他客户端（Codex / Cursor / Continue / Aider / VS Code+Copilot / OpenCode）
位置不同，用 `aiopsec scan` 查本机实际情况。

### 最容易忽略的：`shell-snapshots/`

会话里执行过的命令会把**环境变量**一起写进去。如果你 export 过 API key，
它在快照里。

### 三个立刻能做的动作

```bash
aiopsec scan                        # 看你机器上实际有什么
aiopsec harden --apply              # 关遥测 + 限制 Copilot 读文件
aiopsec hook --install --apply      # 提交 prompt 时自动拦截身份字段
```

### 一个致命细节

`<project>/.claude/settings.json` 会被 `git commit` 带走。里面可能有 hook 脚本、
本地路径、内部提示词。

```bash
printf '.claude/\n.cursor/\n.continue/\n.codex/\nAGENTS.md\nCLAUDE.md\n' >> .gitignore
```

已经提交过的：`git rm -r --cached .claude` + `git filter-repo` 清史。

## 2. 提示词卫生：只做机械性的一条

### 送进 LLM 的文本，按「永久留存 + 可能被调取 + 可能进入训练」对待

**真正会贴的东西**（工具检测这些）：

```
API key / 私钥 / Bearer token / 数据库连接串
公司邮箱（直接暴露雇主）
内网 IP / 内部主机名
客户或同事的数据
```

**不必担心的**（工具已砍，误报率高于收益）：

```
中国手机号 / 身份证 / 银行卡 / 车牌 —— 几乎不会以明文形态出现在给 AI 的文本里
                        误报率极高：订单号、日志、测试数据都像
座机 / Telegram 用户名 —— 同上
```

真要发这类信息，**手工改**，别指望正则。

### 上下文污染

```
同一会话里先聊私事再聊敏感任务 → 前者进后者上下文
memory 开着 → A 里写的进 B 的加载上下文
服务端即使关了 memory，仍可能按账号聚合
```

敏感任务**开新会话**。不同项目**用不同账号**。

### 别在会话里做的事

```
问销赃/交易渠道           动机坐实，且永久留存
贴真实凭据"帮我看看"     换成同结构的脱敏样本
让 AI 生成含真实身份的简历   真实案例里这就是破点
同一账号先聊身份再聊任务   上下文 + 账号双重关联
```

## 3. 环境指纹：一致性本身就是信号

对手不需要破解什么，只需要**对比**。三个维度对不上就露馅：

```
本地时区      vs  出口 IP 所属时区
系统语言      vs  出口 IP 所属国家
主机名/用户名  vs  是否是可跨设备关联的稳定标识符
```

```bash
aiopsec env                # 自动查这三项
aiopsec env --offline      # 不联网
aiopsec env --ip 1.2.3.4   # 查指定 IP 归属
```

**但这只是提醒，不是防护。** 真正的问题是"你为什么要让它们不一致"——
大多数时候的答案是"不需要"，那就统一。

### 隐形的元数据

即使内容加密，连接本身仍泄漏：

```
TLS SNI（目标是谁）—— 除非用 ECH
流量模式（时长/频率/包大小）—— 可指纹客户端
活跃时段 —— 直接映射时区
```

对策按强度递增：Tor（流量匿名）→ CDN 前置（混在别人流量里）→ ECH（隐藏 SNI）。
普通任务不需要走这条路。

## 4. 本地模型：什么时候真的需要

**默认不需要。** 大多数场景下，零留存渠道 + 假身份就够。

**以下情况必须自托管**：

```
数据涉及第三方个人信息   （法律义务，见下）
数据是客户数据 / 生产凭据 / 商业秘密
需要"绝对不出本机"的保证
对手是国家级
你无法核实服务商政策是否真的被执行
```

### 三种部署

```bash
# Ollama（最简）
OLLAMA_HOST=127.0.0.1:11434 ollama run qwen2.5:14b
ss -tlnp | grep 11434        # 确认只绑本地

# llama.cpp（可控性最好）
./build/bin/llama-server -m model.gguf --host 127.0.0.1 --port 8080

# vLLM（需 GPU，⚠️ 一定要关请求日志）
python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen2.5-14B --host 127.0.0.1 \
  --disable-log-requests        # 默认会把 prompt 打到日志
```

### 网络隔离层级

```bash
--host 127.0.0.1                          # 必要但不充分
sudo unshare -n -- <cmd>                   # 进程完全无网（Linux）
sudo ip link set eth0 down                 # 物理断网
```

验证：`curl -s --max-time 3 https://api.ipify.org` 应该失败。

### 一个硬边界

**本地部署 + 本地模型 ⇒ 厂商封号无效。**

真实案例（2026 年公开报告）：一个国家级监控平台完全本地部署，
事后研究者写道"账号层面的执法措施不影响已部署的产品"。

⇒ 治理必须在能力固化前介入。事后封号只对还在用 API 的人有效。

## 5. 清理：能做什么，不能做什么

```bash
aiopsec shred              # 预演，看会动什么
aiopsec shred --force      # 执行（urandom 覆写 + fsync）
```

默认只清**会话/历史/memory/snapshot**，配置与凭据保留。
`--include-config` 才连配置一起清。

### 工具做不到的

```
SSD + TRIM        覆写不保证擦除旧块
btrfs/ZFS/APFS    写时复制，快照里可能有旧版本
备份/同步服务     OneDrive / iCloud / Time Machine 可能已上传
剪贴板历史       Windows Win+V
崩溃转储         core dump 可能含完整内存
shell history    命令行参数里的 key
编辑器 undo/swap vim .swp / VS Code History
```

**唯一可靠的方案**：全盘加密（LUKS / BitLocker / VeraCrypt）
+ 密钥不落盘 + 一次性 VM。

不是矫情——这是取证学的基本事实，不是理论。

## 6. 三个敏感度档位

### A — 日常（防本地取证 + 意外泄漏）

```bash
aiopsec scan
aiopsec harden --apply
cat <要发的> | aiopsec check
每次任务后 aiopsec shred --force
```

成本：5 分钟。防脚本级取证。

### B — 敏感（防服务商 + 防关联）

```
A 全部 +
· 走零留存 API 渠道，或独立账号
· 假身份模板预造（~/.ai-pseudo）
· 会话目录 tmpfs / VeraCrypt
· 出网走自建无日志代理
· 不同项目不同账号
```

### C — 高敏（需断网）

```
B 全部 +
· 本地模型 + 断网（unshare -n）
· 一次性 VM，任务后销毁
· 全盘加密
· 与日常机零网络零文件往来
· 硬件隔离
```

## 7. 三个最容易忽略的点

```
① shell-snapshots 吞 env 变量
   会话里 export 过的 key 都在里面

② 项目 .claude/ 会被 git 提交
   已提交的要清史，不只是 gitignore

③ 改了 base_url 不等于不外联
   客户端可能仍向厂商发遥测。抓包验证，不是看配置
```

## 8. 法律边界

技术脱敏**不免除**法律义务。

向境外模型转发**第三方个人信息**，在《个人信息保护法》下属于
「向第三方提供」+「出境」，需：

```
第 23 条    单独同意 + 告知接收方名称/联系方式/目的/种类
第 38~39 条 出境须安全评估 / 认证 / 标准合同之一 + 另行单独同意
第 55 条    事前个人信息保护影响评估
第 57 条    发生泄露须通知个人并报告
```

把客户数据脱敏后再发给境外模型，**在法律上仍是同一件事**。

自托管能解决"出不出网"，不能解决"该不该处理"。

## 9. 判断框架

对手看到 8 个可关联的源。断掉任意一个不够，要断的是"这些源能否指向同一人"。

```
源 1  基础设施    IP / ASN / 托管商 / 端口 / 证书
源 2  时间        时区 / 活跃时段 / 作息
源 3  语言        用词 / 拼写 / 措辞习惯 / code-switch
源 4  内容        提示词里的身份字段 / 项目代号
源 5  账号        邮箱 / 支付 / 昵称 / 跨服务复用
源 6  客户端      落盘文件 / telemetry ID / 版本
源 7  行为        并发模式 / 节奏 / 工具偏好
源 8  关联        跨会话 / 跨账号 / 跨项目同一性
```

**2026 年公开的真实案例，攻击者的技术层伪装都做得很好**
（12 国 IP、9 个代理、多模型栈），栽的都是上面某一源：
工作目录开成公网读、提示词里写真实身份、账号跨案复用。

技术层 AI 能补。人的 OPSEC 补不了。

## 10. 八个误区

| 以为 | 实际 |
|---|---|
| 删了会话记录就没事 | SSD/CoW 下覆写不保证擦除；备份可能已同步 |
| 无痕模式够用 | 只防本地历史，不防网络观测和服务端留存 |
| 关了 memory 就干净 | 服务端仍可能按账号聚合 |
| 用了代理就安全 | 免费代理本身就是采集点 |
| 脱敏了姓名就行 | 措辞习惯/时区/语言组合仍可指纹 |
| 本地小模型就安全 | 模型文件、日志、缓存仍在磁盘 |
| key 放 env 里就行 | env 会进 shell snapshot 和进程列表 |
| 换个说法问同一件事没事 | 语义等价会被聚类 |

## 11. 工具覆盖不到的

```
真实姓名 / 昵称 / 学校 / 公司 / 职级
语义关联（"我上周去的那家店"）
剪贴板历史 / 备份服务 / 浏览器 LocalStorage 内容
磁盘物理擦除
法律判断
```

**工具降低机械失误，不替代判断。**

通过 `aiopsec check` ≠ 安全。
