# AI 提供商留存政策对照

**本文档是方法论 + 检查模板，不是政策快照。** 各厂商条款会变，用之前必须自己去官网核对。

最后核对日期：**2026-10-10**（示例值，请自行更新）

---

## 1. 必查三件事

去服务商的隐私页 / 数据处理页 / 企业条款页，确认：

```
1) 数据留存多久？
   · 0 天（zero retention）
   · 30 天（常见默认）
   · 永久 / 未明确 ← 最危险
   · 分档：API vs 消费版不同

2) 是否用于训练？
   · 默认关 / 默认开 / 需手动关
   · 企业版通常默认不训练
   · 关了之后是否有"即使关了也可能用于安全审核"的例外

3) 是否人工审核？
   · 完全无人工
   · 标记后人工看（常见）
   · 安全/滥用检测目的
```

**把答案写下来存档**，附上核对日期和 URL。政策变了要能发现。

## 3. 通用规律（跨厂商）

```
· 消费版（Web/App）：通常默认留存 + 可能训练
· API：留存较短（常见 30 天），训练默认关（多数厂商）
· 企业版：默认不训练，可谈零留存（DPA 里写）
· 自托管：你控制，但要自己负责加密与日志
```

**关键**：**"关闭训练" ≠ "不留存"**。留存是独立的。要同时确认两项。

---

## 4. 降低留存影响的措施

无论政策如何，做这些：

```
□ 用 API 而不是 Web（API 通常留存更短、无广告画像）
□ 用企业版 / Team 版（默认不训练）
□ 签 DPA（数据处理协议），明确零留存
□ 开零留存选项（若提供）
□ 关"改进服务" / "帮助训练" 等开关
□ 关历史记录 / 对话保存
□ 关个性化
□ 涉第三方个人信息时，走合规路径（见 threat-model.md）
```

---

## 5. 必须自托管的场景

即使用最好的第三方政策，以下场景也应自托管：

```
· 数据涉及第三方个人信息（法律义务）
· 数据是客户数据 / 生产凭据 / 商业秘密
· 需要"绝对不出本机"的保证
· 对手是国家级
· 你无法核实政策是否真的被执行
```

---

## 6. 自托管方案

见 `local-models.md`。核心三条：

```
1) 只绑 127.0.0.1（不监听 0.0.0.0）
2) 关请求日志（vLLM 需 --disable-log-requests）
3) 磁盘加密 + 模型目录也在加密卷里
```

## 7. 中转 / 转售渠道 —— 高风险

**不要用**来路不明的"折扣 API 中转"。

真实案例（Anthropic 2026-09 报告，GTG-50021）：

```
表面: 提供打折的 Claude 访问
实际: ① 流量被静默代理到另一个模型（你买的不是你以为的）
      ② 客户端工具是凭据收割器，偷你的账号凭据
      ③ 偷到的凭据卖给其他中转商用于恶意用途

IOC:
  awstore[.]cloud      假 Claude 转售门面
  kiro[.]cheap         假 Kiro 转售门面
  sys-tools[.]cfd      C2
  holdboost[.]store    恶意软件平台
  aws-us-east-3[.]com  AWS 仿冒域
```

**判据**：任何要求
- 把流量绕经不明中间方
- 安装非官方客户端
- 提供账号密码"代为配置"

⇒ 视为凭据窃取风险，不是采购机会。

## 8. 自查清单

```
□ 已核对所用服务的留存时长（附日期）
□ 已核对是否用于训练（附日期）
□ 已核对是否人工审核
□ 已关闭所有"改进服务/训练"开关
□ 已关闭对话保存 / 历史记录
□ 企业场景已签 DPA
□ 没有用任何来路不明的 API 中转
□ 涉第三方个人信息时走的是合规路径，不是只做脱敏
□ 高敏场景已转自托管
□ 政策变更时有复核机制（定期重查）
```

## 9. 政策变更监控

```bash
# 简单做法：存一份政策页面哈希，定期比对
url="https://example.com/privacy"
curl -sL "$url" | sha256sum > ~/.ai-provider-hashes/example.txt
# 定期跑
curl -sL "$url" | sha256sum | diff - ~/.ai-provider-hashes/example.txt \
  && echo "政策未变" || echo "⚠ 政策变了，重新核对"

# 或订阅厂商的 changelog / privacy-updates
```
